Patch summary and preserved interface

The following observations come from a static comparison of voucher-before.py and voucher-after.py, not execution:

  • The former used-state guard rejected only another actor. The new guard rejects any used voucher, including same-actor replay, with already_used.
  • New guards reject any state other than active with inactive_voucher, and reject now >= voucher.expires_at with expired_voucher. The expiry boundary is inclusive.
  • After the checkpoint, the code looks up the voucher again and repeats unknown, used, inactive and expiry checks inside the second lock before calling _commit_redemption(voucher, actor).
  • The module description now identifies the local, single-process fixture.

The imports, VoucherService(VoucherStore) class and public signature redeem(self, code, actor, now, checkpoint=None) are unchanged. Unknown-voucher handling remains. The optional checkpoint() call and its scheduling-seam comments remain between the lock blocks, outside the lock.
